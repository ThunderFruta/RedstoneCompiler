# N2 — One shared physical-rule contract

**Status:** necessary requirement.

**Primary owners:** `PhysicalDesign/Redstone/` and
`PhysicalDesign/Contracts/`.

## Goal

Ensure that placement masks, routing resources, route claims, final graph
checks, shortcut evaluation, and rendered block states apply the same versioned
physical and electrical rules.

## Required contract

Every physical-rule decision identifies:

- Model and technology versions.
- The query performed.
- Positions, transforms, and orientations examined.
- Occupancy, support, headroom, and required-air scope.
- Connectivity and electrical-influence scope.
- Directed-power and repeater assumptions.
- Timing and state assumptions, when applicable.
- Required claims and conflicting claims.
- `Legal`, `Illegal`, or `Unknown` outcome.
- Concrete reason and evidence identity.

## Boundary rules

- Consumers query the shared model; they do not implement private variants of
  physical legality.
- Rendering consumes checked model decisions rather than defining routing
  behavior.
- Resource construction receives the selected technology/model identity.
- Cheap early queries and exact later checks refine the same rule contract.
- `Unknown` triggers refinement or an unresolved outcome, never a pass.

## Version and reuse rules

A whole-model fingerprint provides conservative identity but is insufficient
for selective stale salvage. Reusable results also expose query-level dependency
identity or use an explicit model compatibility table.

A changed model version invalidates applicable old claims unless the model
proves equivalence for the exact query scope under [N6](../N6/N6.md).

## Acceptance

- All physical-design consumers agree on the same fixture decisions.
- Version changes invalidate exactly the affected caches and proofs.
- Model disagreements with MCHPRS or Fabric are retained as regressions.
- No consumer silently substitutes a local rule for an `Unknown` answer.
