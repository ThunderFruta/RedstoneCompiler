# N5 — Explicit, non-fail-fast physical acceptance

**Status:** necessary requirement.

**Primary owners:** `Validation/` and `Tools/Routing/`.

## Goal

Run and record every planned acceptance case, preserve authoritative physical
checks, and compare correctness and performance only across equivalent accepted
outputs.

## Required matrix

- Run the complete seven-case expanded matrix without fail-fast skipping.
- Require all four HalfAdder input combinations.
- Require all 512 CLA4 input combinations.
- Preserve passing FullAdder, RCA4, and RCA8 behavior.
- Record every planned case as passed, failed, inherited failure, or `not-run`.
- Never treat an absent or environment-blocked phase as passed.

## Required physical gates

- Required schematic and physical-design artifacts exist.
- Exact truth-table behavior is correct.
- Capacity-one ownership has no conflicts.
- No unresolved physical claims remain.
- No fallback invalidates the authoritative claim.
- MCHPRS validation passes for its required scope.
- The required Fabric canary passes.
- Fabric observes 40 unchanged ticks within the 200-tick bound.
- Fixture identity, source identity, and evidence provenance match the run.

## Comparison dimensions

- Logical semantics and exact physical truth tables.
- Footprint, height, and maximum dimension.
- Wire, support, and repeater material.
- Connection length, congestion, bends, and delay.
- Wall time and named stage timings.
- Memory use and retained cache size.
- Useful Python and native CPU work.
- Preempted, abandoned, stale, and salvaged work.

Normalize only non-semantic metadata such as timestamps, checkout paths,
revisions, and source-location fields when comparing reports. Do not normalize
away electrical results, geometry, routing policy, failures, or ownership.

## Stale-result acceptance cases

- A distant non-interfering change permits local salvage.
- A new nearby occupancy conflict rejects salvage.
- A non-overlapping change inside electrical-influence range rejects salvage.
- Unchanged cell coordinates with blocked pin access reject R3 salvage.
- Partial orientation salvage retains only certified variants.
- A feasible route survives while its congestion score is recomputed.
- Domain expansion rejects an old infeasibility proof.
- A recognized monotonic constraint strengthening preserves a scoped proof.
- A new candidate invalidates old optimality without invalidating feasibility.
- A late worker result never commits without coordinator review.
- Salvage enabled and disabled produce equivalent accepted behavior.

## Evidence

Acceptance runs use a fresh output root and retain concise and raw reports,
manifests, hashes, typed failures, physical-design artifacts, fixtures, and
backend observations. Missing evidence blocks the corresponding claim.
