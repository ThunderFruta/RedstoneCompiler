# R1 — Delay expensive physical expansion

**Status:** a bounded portfolio-local oriented static-geometry reconstruction
cache is an uncommitted Batch 3 candidate; broader lazy physical expansion
remains target behavior.

**Primary owner:** `PhysicalDesign/Routing/Global/`.

## Goal

Represent search candidates compactly and postpone exact wire, support,
repeater, block, and ownership expansion until a candidate requires exact
evaluation or materialization.

Full schematic emission already occurs late. R1 concerns the repeated physical
expansion and copying performed while exploring candidates before that final
rendering step.

## Current implementation status

The owner branch records completed reconciliation of the legacy R1 history and
repository-wide outcome-test cleanup at `5cd4456`. Neither establishes compact
candidate representation, deferred exact expansion, expansion/copying metrics,
or lazy-versus-eager physical-artifact equivalence. Existing cache mechanisms
therefore do not prove R1 behavior.

The uncommitted Batch 3 candidate adds one narrower R1 mechanism to the
pin-aligned packed-cluster portfolio. After the process-global portfolio cache
misses, one finite context retains the exact four origin-relative immutable
masks produced by `BuildPlacedCellGeometryWithKeepOut` for each canonical cell
kind, quarter-turn rotation, and legal mirror. Later XYZ translations use the
same masks and recompute electrical exclusions through the full current
technology rule. The current macro domain has 16 possible entries: four each
for INPUT and OUTPUT and eight for mirror-capable NAND.

The context rechecks a versioned, complete value identity and exact loaded
object generation before every resolution. It covers all current public macro
values; the exact key, concrete class, size and complete block state of every
loaded template entry, including entries without a macro; and the full frozen
routing-technology value and concrete class. Missing, malformed, unsupported,
or changed identity cannot hit; it preserves the eager error or calls the same
public producer and records a stable fallback reason. The context is neither
global nor retained in a portfolio. A process-global portfolio hit creates no
oriented context and returns a separate all-zero current-work receipt.

The process-global portfolio key independently binds that same complete
producer-context value and exact loaded generation before lookup, including
when the caller requests eager/no-oriented-cache execution. A changed macro,
any loaded template state or object generation, technology value or class, or schema
therefore rebuilds the portfolio under the current context rather than
replaying stale states. If the identity is unsupported or cannot be reproduced,
global lookup and publication are skipped. Identity checking itself is not an
oriented geometry request or avoided expansion.

Every uncached portfolio evaluation uses an explicit identity-attesting
resolver. Cached mode uses the finite oriented-mask context; eager mode calls
the same public producer for each request without retaining masks. Both modes
bypass the three legacy transform-only geometry, exclusion and access-ray LRUs
inside this portfolio, while unrelated no-context callers retain their existing
behavior. Global publication requires the resolver to attest the exact
pre-lookup producer identity throughout the evaluation.

The immutable receipt counts requests, hits, misses, eager fallbacks and
reasons, public-producer calls, avoided producer calls, translation
materializations, retained entries, the finite maximum, and the separate
portfolio-cache-hit state. It is excluded from portfolio equality. These
fields reject booleans, floats and negative counts, noncanonical fallback
reasons, and retained-entry bounds outside the declared maximum. Recursive or
otherwise unsupported template state takes the eager fallback and cannot leave
a partial identity or global entry. These
counts make no wall-time, CPU, allocation, byte, block-copy, or prior-LRU
comparison claim. The candidate does not defer route, proof, ownership,
support, or final block-map construction, and it does not implement R5
topology reuse or N6 stale-result salvage.

The uncommitted Batch 2 prerequisite candidate on `Reuse-And-Salvage`, based on
`e4609e7f96a65a437ff33c04300f1111204e4081`, verifies one narrower exact-current
contract: `BuildRoutingResources` builds one nonempty static geometry/resource
graph lineage, and `ForkRoutingResourcesWithSharedStaticGeometry` gives sibling
envelope and candidate contexts the same immutable static-geometry sets and
the same current-lineage resource graph while starting with fresh native, proof,
portal, candidate, assignment, and prepared state. The graph itself is a
mutable dataclass whose private pure region/claim memoization is intentionally
shared for this lineage. The fork test seeds every public fork-local mutable top-level container
and representative tuple/Any state before forking, then compares every
fork-local field with a fresh `RoutingResources` dataclass default; only static
geometry and the resource graph are shared. Its oracle rotates the public NAND
template explicitly, checks occupancy/electrical/solid sets and a foreign
frozen wire, then observes public region and route-claim behavior. Current
`WorkCheck` output is retained as diagnostic evidence only; no event schema or
choreography is made contractual here. This is neither lazy physical expansion
nor a measured reconstruction/copying reduction, and it does not establish
cross-placement reuse.

## Required behavior

- Represent candidates using cell identities, transforms, ports, corridors,
  reservations, bounds, and physical-rule versions.
- Cache immutable cell and orientation geometry, clearance masks, access masks,
  and other reusable local facts.
- Distinguish lower bounds, heuristic envelopes, exact claims, and final block
  states.
- Expand exact candidate claims only when required by feasibility checking,
  global compatibility, objective measurement, or commitment.
- Construct the complete block map only after selecting and statically checking
  a legal design.
- Record expansion and copying avoided, exact refinements performed, cache
  hits, cache misses, and discarded materializations.

## Correctness boundary

Compact representations must preserve every constraint needed to refine the
same physical model later. Laziness is not permission to ignore support,
headroom, electrical influence, directed power, repeater behavior, or exclusive
resource ownership.

A cheap candidate check may return `Unresolved` when exact expansion is needed.
It may not turn an unknown physical property into a pass.

## Reuse and stale-result rules

Each cache entry declares the claim it establishes:

- Static template geometry.
- One oriented or mirrored mask.
- One pin-access possibility.
- One approximate routing envelope.
- One exact route-claim set.
- One materialized physical fragment.

Reuse is authorized only for that declared layer. Reusing an orientation mask
does not authorize reuse of an old route, score, proof, or ownership assignment.
Stale entries follow [N6](../../N/N6/N6.md); exact current identity remains the normal
fast path.

## Acceptance

- Exact refined claims agree with eager construction for representative cases.
- Lazy and eager modes produce equivalent accepted physical artifacts.
- No cache hit crosses an incompatible model, orientation, topology, policy, or
  reservation dependency.
- Measured expansion, copying, and discarded materialization decrease without
  weakening physical validation.
