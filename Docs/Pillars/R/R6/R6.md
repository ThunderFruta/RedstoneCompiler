# R6 — Persistent, priority-aware routing workers

**Status:** target behavior.

**Primary owner:** `PhysicalDesign/Runtime/`.

## Goal

Keep Python workers alive across the routing run, supply them with meaningful
independent work, and use otherwise-idle capacity for low-priority work without
delaying critical routing decisions.

## Required behavior

- Retain worker processes and eligible worker-local caches across operations.
- Schedule placement alternatives, interface alternatives, route searches,
  local proofs, geometry preparation, and repair work in meaningful batches.
- Count Python processes and native threads under one CPU-admission policy.
- Bound queued payloads, speculative results, retained caches, and native
  contexts under one memory policy.
- Propagate an absolute deadline, work cap, cancellation contract, and maximum
  non-yield interval into every task.
- Keep coordinator commitment short and deterministic.
- Use spare admitted capacity for optional stale-result review, cache warming,
  proof minimization, or non-essential optimization.
- Ensure opportunistic work is semantically optional and rapidly preemptible.

## Priority classes

| Priority | Typical work | Preemptible |
|---|---|---:|
| Critical | Work needed for the coordinator's next routing decision | Only for cancellation or deadline enforcement |
| High | Current repair or alternatives likely to unblock the incumbent | Normally only at declared safe points |
| Normal | Active-portfolio breadth search | Yes |
| Opportunistic | Stale-result review, cache warming, speculative quality work | Yes, within the declared bound |
| Maintenance | Cache indexing, compaction, and eviction preparation | Yes; only with CPU and memory headroom |

Workers and subsystems may recommend priority changes but cannot change their
own semantic priority.

## Explicit promotion and demotion

Task priority changes only through an immutable coordinator decision containing
the task identity, scheduling epoch, old and new priority, reason, active
frontier, current snapshot, dependency contract, budget, and granted or revoked
resources.

Promotion:

- Identifies the current coordinator decision the task can advance.
- Binds the task to a current-snapshot request or an explicit N6 review.
- Creates a new scheduling epoch or continuation capability.
- Assigns bounded CPU, native-thread, memory, work, and deadline budgets.
- Does not establish correctness, freshness, ranking, or acceptance.

Demotion:

- Lowers the priority of a task that remains live or resumable.
- Revokes critical-only capabilities and leases.
- Makes the task safely preemptible.
- May retain bounded opportunistic state and immutable checkpoints.
- Permits later explicit promotion if dependencies remain valid.

## Demotion versus termination

Demotion and termination are different operations:

| Property | Demotion | Termination |
|---|---|---|
| Meaning | Continue only if lower-priority capacity permits | This task instance will perform no more work |
| Ends execution permanently | No | Yes |
| Same task may resume | Yes | No |
| Same task may be promoted later | Yes | No |
| Releases critical-only resources | Yes | Yes |
| Releases every live task resource | Not necessarily | Yes |
| May retain bounded live continuation state | Yes | No |
| May retain immutable completed results/checkpoints | Yes | Yes |
| Stops the persistent worker process | No | Normally no |
| Establishes a routing conclusion | No | No |

Demotion is a scheduling transition. A demoted task may run, yield, pause,
checkpoint, queue, or later be promoted.

Termination is a lifecycle transition. A terminated task cannot resume or be
promoted under the same identity. Continuing its work requires a new task with
a new identity, current dependency contract, and budget.

Cancellation is a request or reason; termination is the resulting lifecycle
state. A cancellation request does not prove that termination has completed.

## Safe demotion

Before the scheduler considers a task demoted, the task must:

- Reach a consistent safe point.
- Stop submitting critical child work.
- Release critical worker and native-thread permits.
- Release or transfer exclusive leases.
- Remove pending commit access.
- Reduce memory to the opportunistic allowance.
- Preserve only immutable, dependency-stamped progress.

The scheduler does not count resources as free until release is acknowledged.

## Termination

Successful task termination must stop execution, prevent further child work,
release all live task resources and capabilities, close private execution
contexts, and mark unfinished claims incomplete. It may retain only completed
immutable results, valid finalized checkpoints, diagnostics, and provenance.

Terminal lifecycle states remain distinct:

```text
Completed
TerminatedGracefully
TerminatedForced
Failed
```

Task termination normally leaves the persistent worker process alive. Worker
termination is a separate runtime recovery action for crashes, failure to
yield, unrecoverable native work, or runtime shutdown.

## Opportunistic work

When critical work arrives, the scheduler uses an idle worker or preempts the
lowest-value eligible opportunistic task. Checkpointing is allowed only when it
is bounded, cheap, immutable, and does not delay worker release. Otherwise the
temporary progress is abandoned.

The coordinator never waits for opportunistic work by default. It may promote
an optional task only when that task is expected to advance a current required
decision more cheaply than replacement work.

## Acceptance

- Worker pools persist without leaking run-specific mutable state.
- Critical work starts within the declared preemption bound under full
  opportunistic load.
- Demotion releases critical-only resources but preserves resumability.
- Termination releases every live task resource and forbids same-task resume.
- Task termination does not unnecessarily terminate the persistent worker.
- Worker count and completion order do not change deterministic accepted
  results.
- Telemetry accounts for useful, preempted, abandoned, checkpointed, promoted,
  demoted, and terminated work.
