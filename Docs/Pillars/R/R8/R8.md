## Goal

Keep detailed routing telemetry enabled while presenting only concise outcome,
timing, CPU, and output-location information in the terminal. Preserve detailed
events and samples in retained run artifacts.

## Current implementation status

The committed R8/N5 checkpoint preserves the requested strategy and command aliases,
the independently resolved strategy, explicit no-fallback state, canonical
policy/source-template identities and hashes, evaluator outcome, archive, and
routing-design snapshot. Archive source-content stability is tri-state: two
complete observations with matching canonical SHA-256 and exact nonnegative
file count evaluate `true`; complete contradictions evaluate `false`; absent,
incomplete, malformed, or wrongly typed observations are unknown. The newest provenance
check is authoritative, so malformed newest evidence cannot fall back to an

This repair changes reporting and evidence contracts only. It does not change
routing decisions, physical behavior, or acceptance evaluation policy.

## Required coverage

- Coordinator preparation, dispatch, merge, commit, and wait time.
- Task ready, queued, running, completed, cancelled, failed, stale, and
  discarded states.
- Worker startup and shutdown.
- Serialization and interprocess transfer cost.
- Python process and native-thread CPU use.
- Cache hits, misses, invalidation, eviction, and useful reuse.
- Memory used by queues, candidates, caches, native contexts, and retained
  evidence.
- Exact work counters versus sampled CPU observations.
- Work discarded during retries.
- Current, stale-unreviewed, salvage-started, partially salvaged, salvaged,
  salvage-rejected, revalidated, and committed results.
- Task promotion, demotion, cancellation, graceful termination, forced
  termination, and worker termination.
- Time from demotion request to safe yield and from promotion to dispatch.

## Reporting boundary

Lower layers emit typed events through a narrow sink. They do not import
terminal formatting or application reporting policy. `App/` aggregates events,
writes detailed artifacts, and emits the concise terminal result.

Telemetry must not change worker limits, search policy, deadlines, candidate
ordering, acceptance, or physical behavior.

## Acceptance

- Every retained task has a complete terminal lifecycle or an explicit partial
  record after process termination.
- Priority and stale-result transitions are reconstructable.
- Sampled and exact measurements are clearly distinguished.
- Terminal output remains concise while raw details remain available in run
  files.
- Telemetry overhead is measured and bounded.
