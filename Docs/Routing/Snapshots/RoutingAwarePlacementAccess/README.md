# Routing-aware placement and access snapshot bundles

These directories are timestamped evidence generated by
`Scripts/CaptureRoutingDesignSnapshot.py` and treated as immutable after a
completed capture. The normative architecture is
[RoutingAwarePlacementAccessDesign.md](../../Active/RoutingAwarePlacementAccessDesign.md),
and the append-only interpretation log is
[RoutingAwarePlacementAccessSnapshots.md](../../Active/RoutingAwarePlacementAccessSnapshots.md).

## Identity semantics

Schema v2 exposes two aggregate identities and retains per-file
`SHA256SUMS`:

- the **exact-byte evidence identity** changes when any schema-defined captured
  evidence byte identity changes;
- the **portable-semantic evidence identity** normalizes only the explicitly
  declared capture-time, absolute-location, snapshot-name, and publication-
  path fields; and
- `SHA256SUMS` verifies the exact generated files and copied artifacts in one
  bundle.

The schema and its normalization rules are part of each aggregate identity.
Never compare a v1 `CanonicalEvidenceSha256` directly with either v2 identity.
The original `20260828T001726Z` v1 digest is only the digest of its reduced v1
canonical JSON projection; see the explicit correction entry in the
[append-only snapshot log](../../Active/RoutingAwarePlacementAccessSnapshots.md).

## Captures

- [`20260828T001726Z`](20260828T001726Z/Snapshot.md) -- durable current-source
  CLA4 placement-failure baseline, including raw acceptance/failure/netlist
  evidence and machine-readable source metrics. This is a schema-v1 bundle;
  its per-file hashes remain valid, but its canonical digest is not either v2
  aggregate identity.
- [`20260828T004131Z`](20260828T004131Z/Snapshot.md) -- schema-v2 correction
  capture with separately defined exact-byte and portable-semantic identities,
  double-read source/runtime guards, acceptance-manifest validation, and
  verified absence of CLA4 success artifacts.
- [`20260828T005427Z`](20260828T005427Z/Snapshot.md) -- final hardened schema-v2
  capture; adds immediate pre-publication aggregate-identity and snapshot-ID
  recomputation plus adversarial post-build mutation rejection.

Each final directory must be fresh. The generator builds a fresh hidden
staging directory beneath this root, verifies its contents, and then renames
it to the final timestamped name. This is an application-level publication
sequence, not a transactional, crash-durable, or filesystem-atomic guarantee.
A process or host crash can leave a hidden staging directory; such a directory
is incomplete evidence and must never be listed as a capture.

Verify a completed final directory from inside it with:

```bash
sha256sum --check SHA256SUMS
```

Do not replace an existing final directory or edit generated evidence in
place. Capture a new timestamp and append its interpretation to the snapshot
log.
